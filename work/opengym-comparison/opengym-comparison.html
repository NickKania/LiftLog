Already local-first

openGym also has a standalone phone mode with local files and native reminders. Its optional server adds pairing and sync. For weight-app, keep SwiftUI + SQLite as the primary product and adapt the training ideas. Source

Keep the advantages

Preserve immutable template versions, actual-versus-planned snapshots, active-session recovery, transactional saves, iCloud backups, Live Activities, and explicit review of assistant changes.

Compute on device

PRs, exercise trends, progression targets, muscle volume and rotation state can come from local records. Use the same deterministic calculations in screens and assistant tools. Offline progress and planning should not require a ChatGPT account.

Correctness first

Finishing currently removes unfinished sets. Preserve the original planned set count and skipped outcomes before adding automatic progression. Handle unit conversion, assisted lifts, per-side reps, and “one dumbbell vs both” explicitly. Corrections must recompute PRs and future suggestions.

Catalog reuse

The vendored 876-exercise dataset already contains equipment, primary/secondary muscles and instructions. Expose those fields first. Images are not currently bundled. Keep stable exercise IDs and historical snapshots when enriching the catalog.

Privacy by choice

Keep Health access explicit. Current Health support reads session heart rate, energy and steps for tagged assistant messages; it does not log body weight or write workouts. Add body metrics and photos locally, with clear backup scope and separate permission choices.

Different priorities

Defer passkey accounts, admin dashboards, Docker deployment and server audit logs. Multi-device sync is a separate project: existing iCloud backup restore replaces the dataset and does not merge edits. Broader AI providers or an external MCP interface are optional extensions, not prerequisites for training features.

Port ideas carefully

openGym code is AGPL-3.0. Its exercise animations have separate Gym visual restrictions, so they are not a drop-in asset source for this app. Prefer the existing catalog and independently implemented native flows; check licensing before copying code or media. Third-party notices
